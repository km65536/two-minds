# TWO MINDS

夜の部屋で、テーブルをはさんで向かい合う二人 ―― ひらめきから考える **レオ** と、分析から考える **ミナ**。
二人は Gemini API によってその場で生まれる会話を、自分たちだけで延々と続けます。
あなたはそれを眺めていてもいいし、好きなときに画面下から話しかけてもかまいません。

- 2D の画面で、左右の二人が向かい合って話す。吹き出しが出て、話している間は口が動き、表情が変わる
- 二人はプレイヤーを待たずに、自分で話題を見つけ、反応し、反論し、脱線し、ときには黙る
- 決まった順番で交互に話すのではなく、同じ人が続けて話すことも、沈黙が訪れることもある
- プレイヤーは第三の参加者。話しかけると、二人がそれぞれのやり方で反応する
- 文脈はこのタブの、いまの会話の間だけ。長期記憶や会話履歴は保存しない

## ローカルで起動する

必要なもの: **Node.js 22 以上**

```bash
npm install
```

```bash
cp .env.example .env
```

`.env` の `GEMINI_API_KEY=` に API キーを書いて（次の節）、起動します。

```bash
npm start
```

ブラウザで <http://127.0.0.1:3000> を開き、「会話をはじめる」を押してください。
API キーがなくても、デモモード（後述）で画面の動きは確認できます。

## API キーの設定（課金されないために）

1. [Google AI Studio](https://aistudio.google.com/apikey) で API キーを発行します。
2. **請求先アカウント（Billing）を設定していないプロジェクトのキー** を使ってください。請求先がなければ無料枠でのみ動き、上限に達するとエラー（429）になるだけで、課金はされません。請求先を設定したプロジェクトのキーだと、無料枠を超えた分が課金されるおそれがあります。
3. キーは **サーバーの環境変数 `GEMINI_API_KEY` にだけ** 置きます（ローカルでは `.env`、Render ではダッシュボード）。ブラウザには一切送られません。`.env` は Git にコミットされません。

### モデルと無料枠について

- 既定のモデルは `gemini-3.5-flash-lite` です。Google の公式モデルページに安定版（stable）として載っていることを確認しています（Google Cloud のドキュメントでは GA 日が 2026 年 7 月 21 日）。変えるときは `GEMINI_MODEL` を書き換えてください。
- 公式の[料金ページ](https://ai.google.dev/gemini-api/docs/pricing)では、Flash-Lite 系のモデルに無料枠（Free of charge）があります。無料枠で送った内容は Google のサービス改善に使われる場合がある、と書かれています。
- **無料枠の回数（1 分あたり・1 日あたりの上限）は、公式ドキュメントで具体的な数値を確認できませんでした。** プロジェクトごとの実際の上限は AI Studio のレート制限の画面で確認してください（[レート制限のページ](https://ai.google.dev/gemini-api/docs/rate-limits)）。無料枠の内容は予告なく変わることがあります。
- このアプリの上限（下の表）は、確認した無料枠の上限より低く設定してください。

> この README の情報は 2026 年 11 月時点で確認したものです。最新の情報は上記の公式ページを確認してください。

## Render の無料 Web Service で公開する

### Blueprint（render.yaml）を使う場合

1. このリポジトリを GitHub にプッシュします。
2. Render のダッシュボードで **New → Blueprint** を選び、リポジトリとブランチを指定します。
3. `GEMINI_API_KEY` の入力を求められるので、キーを入力します。
4. デプロイが終わると `https://<サービス名>.onrender.com` で遊べます。

### 手動で作る場合

**New → Web Service** でリポジトリを選び、次のように設定します。

| 項目 | 値 |
|---|---|
| Runtime | Node（`NODE_VERSION=22` を環境変数に追加） |
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Instance Type | Free |
| Health Check Path | `/healthz` |
| Environment | `GEMINI_API_KEY`（必須）と、必要なら下の表の変数 |

`PORT` は Render が自動で設定し、Render 上ではサーバーは自動的に `0.0.0.0` で待ち受けます。
無料インスタンスはしばらくアクセスがないと休止し、次のアクセスで起動します（最初の表示に時間がかかります）。

## 使いすぎ・不正利用の防止

| 対策 | 内容 |
|---|---|
| 課金されないキー | 請求先のないプロジェクトのキーを使えば、無料枠を超えてもエラーになるだけ（最も重要） |
| サイト全体の上限 | 1 日（太平洋時間）あたり `DAILY_CALL_LIMIT` 回、1 分あたり `RPM_LIMIT` 回 |
| 接続元ごとの上限 | IP ごとに 1 日 `IP_DAILY_LIMIT` 回、1 分 `IP_RPM_LIMIT` 回、リクエスト間隔は `IP_MIN_INTERVAL_MS` 以上 |
| 同時実行数 | `MAX_CONCURRENT` 件まで |
| クライアント側の自主規制 | ブラウザ自身がサーバーの上限より少ない回数に収まるよう間隔を調整する。重複のやり直しで増えた分も数える |
| リトライしない | SDK の自動リトライは無効。Gemini の 429 も再試行しない。通信エラーのやり直しは 3 回まで |
| 出力の上限 | 1 発言は 110 字程度、出力トークンは `GEMINI_MAX_OUTPUT_TOKENS` まで |
| 見ていないときは止まる | 画面を離れた瞬間に生成を止める（戻ると続きから再開）。操作がないまま 40 発言で「まだ見ていますか？」と一時停止 |
| 他サイトからの利用を拒否 | 専用ヘッダーと Origin を確認。リクエストサイズも制限。CSP などのセキュリティヘッダー |
| 緊急停止 | `AI_ENABLED=false` で AI を呼ばず、デモモードだけで動く |
| 上限に達したら | 1 日の上限に達したら、AI ではないと明示したデモモードに切り替えて表示を続ける |

上限の回数はサーバーのメモリ上で数えているので、無料インスタンスが休止・再起動すると数え直しになります。**最終的な歯止めは「請求先のないキーを使うこと」** です。

### 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `GEMINI_API_KEY` | （必須） | Gemini API キー |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | 使用するモデル |
| `GEMINI_MAX_OUTPUT_TOKENS` | `2048` | 1 発言あたりの最大出力トークン数（思考トークンを含む） |
| `GEMINI_THINKING_LEVEL` | （空） | 思考の深さ（`MINIMAL` / `LOW` / `MEDIUM` / `HIGH`）。空ならモデルの既定値 |
| `AI_ENABLED` | `true` | `false` で AI を止め、デモモードのみにする |
| `DAILY_CALL_LIMIT` | `300` | サイト全体の 1 日あたり呼び出し上限 |
| `RPM_LIMIT` | `10` | サイト全体の 1 分あたり呼び出し上限 |
| `IP_DAILY_LIMIT` | `120` | 接続元ごとの 1 日あたり上限 |
| `IP_RPM_LIMIT` | `8` | 接続元ごとの 1 分あたり上限（会話のテンポもこの値で決まる。1 人あたり 1 分に約 7 発言） |
| `IP_MIN_INTERVAL_MS` | `2500` | 接続元ごとの最小リクエスト間隔 |
| `MAX_CONCURRENT` | `3` | 同時に処理する AI リクエスト数 |
| `PORT` / `HOST` | `3000` / `127.0.0.1`（Render では `0.0.0.0`） | 待ち受けポートとアドレス |

## デモモード

API キーがないとき、AI が止められているとき、1 日の上限に達したときは、**デモモード** で動きます。
デモモードの会話は AI ではなく、決まった文型を組み合わせているだけです。ヘッダーに `DEMO` バッジ、開始時と切り替え時に「AI ではありません」という表示が出ます。デモモードでは API は一切呼び出されません。

## 遊び方

- 「会話をはじめる」を押すと、二人が話し始めます。あとは眺めているだけで会話は続きます。
- 画面下の入力欄から話しかけられます（100 字まで）。名前を呼ぶと、その人が先に反応します。
- 右下のボタンで一時停止 / 再開。一時停止中に話しかけると、一人が応えます。
- ほかのアプリやタブに移ると止まり、戻ると続きから再開します。同じタブで再読み込みした場合は「続きを見る」か「新しい会話をはじめる」を選べます。

## しくみ

### 二人の人格

`server/conversation.mjs` の `CHARACTERS` に定義しています。

- **レオ**：直感とひらめきを大切にし、全体像から入る。関係なさそうなものの共通点に気づく。思いついたらすぐ口にし、驚きや喜びを素直に出す。冗談や軽い挑発もする。ただし論理も使え、根拠を確かめて考えを直せる。
- **ミナ**：論理と分析を重視し、細かく分解して考える。根拠と因果関係を確かめ、曖昧な説明を疑う。落ち着いていて、乾いたユーモアや皮肉も。ただし感情は豊かで、意外な発想に興奮したり、自分にもひらめきが訪れたりする。

それぞれのシステム指示には **自分の人格だけ** が書かれ、相手の設定は渡しません。二人の共通のルールとして、

- 知性に優劣はない。どちらもいつも正しいわけではなく、納得したら考えを改め、間違いを認める
- 知らないことは知らないと言う。事実・推測・仮説を区別する
- 二人の間柄は定義しない（友人・恋人などと決めない）。長く話してきた相手として、癖を知り、からかい、ときには真剣に向き合う
- 会話を通じて相手から影響を受けてよい。ただし自分らしさは失わない
- 毎回同じあいさつ、言い換えだけの返事、毎回質問で終わる、毎回結論を出す、不自然に褒める、自分の性格を説明する、といった会話はしない

を伝えています。

### 自律した会話の流れ

1. 次に話す人のために、サーバーがプロンプトを組み立てます（直近の会話、話題の流れ、本人のメモ、状況に応じたヒント）。
2. Gemini は JSON で、セリフ・表情・意図・話題・ジャンル・**言い終えたあとどうしたいか（after）**・会話の勢い（tempo）・覚えておきたい小さなメモ（note）を返します。
3. `after` で次の流れが決まります。
   - `pass`：相手の番（ふつう）
   - `continue`：言い足りないので、同じ人がもう一言続ける（2 発言まで）
   - `silence`：話がひと区切りして、静かな間が訪れる。数秒〜十数秒、吹き出しのない沈黙のあと、どちらかが何気ない一言で話し始める
4. `tempo` で発言の間隔が変わります（盛り上がっているときは短く、じっくり考えているときは長く）。
5. 停滞（短い返事の連続・同じ内容の繰り返し・同じ話題の長続き）、締めくくり、同じジャンルの連続、質問で終わる癖などを検出すると、話題を変える・黙る・質問で終わらない、などのヒントを加えます。話題の例は 14 のジャンルから、最近使っていないものを選びます。
6. 直近と似すぎた発言は 1 回だけ作り直させます。

**意図的な沈黙と待ち時間の区別**：AI の応答待ちのときは、話す人の側に「…」の吹き出しが出て、考え中の表情になります。意図的な沈黙のときは吹き出しを出さず、二人は視線を少しそらし、ヘッダーに「静かな間」と表示されます。通信エラーのときはその旨を表示します。

**表情**：話す人の表情は AI が選んだもの（8 種類）。話している間は口が動き、言い終わると止まります。聞いている人は、相手のセリフの雰囲気（冗談・反論・質問など）に合わせて控えめに表情を変え、ときどきうなずきます。

### プレイヤーの参加

- 話しかけると、名前を呼ばれた人（呼ばれていなければどちらか）が先に反応します。
- もう一人には「すでに相方が反応した」ことが伝わり、別の視点を足す、相方の反応に意見する、聞き返す、二人の話に戻る、などを自然に選びます。必ず全員が答えるわけではありません。
- プレイヤーの発言は、そのあと二人の発言が合わせて 3 つ続いたら「流れの一部」として扱われます（会話の文脈には残ります）。司会者扱いはせず、指示に従う義務もありません。

### 会話の文脈（短期的なものだけ）

- **直近の会話**：最新 16 発言（沈黙とプレイヤーの発言を含む）
- **話題の流れ**：これまでの話題のラベル最大 10 件。古い発言が流れても、前の話題に戻れる
- **各自のメモ**：本人が「覚えておきたい」と返した小さなこと（相手の癖、考えが変わったこと、戻りたい話題）を最大 6 件。**メモは本人のプロンプトにしか入らない**ので、二人の内面は独立したまま

これらは **このタブの sessionStorage にだけ** 置かれます。サーバーにもデータベースにも保存しません。タブを閉じると消え、「新しい会話をはじめる」を選んでも消えます。

## スマートフォン対応

- 画面全体を表示領域ぴったりの固定レイアウト（`position: fixed` + `100dvh`）にし、ページ自体は縦にも横にもスクロールしません。
- 仮想キーボードが出たときは `visualViewport` の実寸に合わせて全体を縮め、入力欄が常に見えるようにしています。
- ノッチやホームインジケーターは `env(safe-area-inset-*)` で避けます。
- キャラクターの大きさは、ステージの **幅と高さの両方** から決めます（コンテナクエリの `cqw` / `cqh`）。どの画面でも二人と吹き出しの領域が両方収まります。
- 吹き出しは古いものから消し、それでも入らないときだけ文字を詰めます。

## 開発

```bash
npm test
```

ユニットテスト（人格・プロンプト・会話状態の分析・上限）と、モックの Gemini サーバーに対して実際にサーバーを起動する結合テストが走ります。API キーは不要で、本物の Gemini には接続しません。

```bash
npm run dev
```

ファイル変更時にサーバーを自動再起動します。

```
server/
  index.mjs         HTTP サーバー（静的配信・API・呼び出し元の確認）
  ai.mjs            Gemini API 呼び出し・エラー変換
  limits.mjs        使いすぎ防止の上限管理
  conversation.mjs  人格・プロンプト組み立て・会話状態の分析
  demo.mjs          デモモードの簡易生成器（AI ではない）
public/
  index.html / style.css / app.js   画面と会話の進行
test/               テスト
render.yaml         Render 用の Blueprint
```
