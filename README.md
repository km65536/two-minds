# TWO MINDS

夜の部屋で、テーブルをはさんで向かい合う二人 ―― ひらめきから考える **レオ** と、分析から考える **ミナ**。
好奇心旺盛な二人は、何気ない話の中から面白いことを見つけ、疑問を持ち、自分なりの考えをぶつけ合いながら、一緒に答えを追いかけます。
会話は Gemini API がその場で生成します。あなたはそれを眺めていてもいいし、好きなときに画面下から話しかけてもかまいません。

- 2D の画面で、左右の二人が向かい合って話す。吹き出しが出て、話している間は口が動き、表情や動作が変わる
- 雑談から「あれ？」を見つけ、仮説を出し合い、反論し、考えを直し、結論にたどり着く（分からなければ未解決のまま）
- 毎回問題を解くわけではなく、雑談や冗談だけの回もある。考え込む沈黙もある
- プレイヤーは第三の参加者。話しかけると、二人は話を止めて反応し、必要なら考えを変える
- Gemini には一連の会話記録をまとめて生成させ、ゲーム側で一発言ずつ再生する（発言ごとには通信しない）
- 文脈はこのタブの、いまの会話の間だけ。長期記憶や会話履歴は保存しない

## ローカルで起動する

必要なもの: **Node.js 22 以上**

```bash
npm install
```

```bash
cp .env.example .env
```

`.env` の `GEMINI_API_KEY=` に API キーを書いて（次の節）、起動します。

```bash
npm start
```

ブラウザで <http://127.0.0.1:3000> を開き、「会話をはじめる」を押してください。
API キーがなくても、デモモード（後述）で画面の動きは確認できます。

## API キーの設定（課金されないために）

1. [Google AI Studio](https://aistudio.google.com/apikey) で API キーを発行します。
2. **請求先アカウント（Billing）を設定していないプロジェクトのキー** を使ってください。請求先がなければ無料枠でのみ動き、上限に達するとエラー（429）になるだけで、課金はされません。請求先を設定したプロジェクトのキーだと、無料枠を超えた分が課金されるおそれがあります。
3. キーは **サーバーの環境変数 `GEMINI_API_KEY` にだけ** 置きます（ローカルでは `.env`、Render ではダッシュボード）。ブラウザには一切送られません。`.env` は Git にコミットされません。

### モデルと無料枠について

- 既定のモデルは `gemini-3.5-flash-lite` です。Google の公式モデルページに安定版（stable）として載っていることを確認しています（Google Cloud のドキュメントでは GA 日が 2026 年 7 月 21 日）。変えるときは `GEMINI_MODEL` を書き換えてください。
- 公式の[料金ページ](https://ai.google.dev/gemini-api/docs/pricing)では、Flash-Lite 系のモデルに無料枠（Free of charge）があります。無料枠で送った内容は Google のサービス改善に使われる場合がある、と書かれています。
- **無料枠の回数（1 分あたり・1 日あたりの上限）は、公式ドキュメントで具体的な数値を確認できませんでした。** プロジェクトごとの実際の上限は AI Studio のレート制限の画面で確認してください（[レート制限のページ](https://ai.google.dev/gemini-api/docs/rate-limits)）。無料枠の内容は予告なく変わることがあります。
- このアプリの上限（下の表）は、確認した無料枠の上限より低く設定してください。

> この README の情報は 2026 年 11 月時点で確認したものです。最新の情報は上記の公式ページを確認してください。

## Render の無料 Web Service で公開する

### Blueprint（render.yaml）を使う場合

1. このリポジトリを GitHub にプッシュします。
2. Render のダッシュボードで **New → Blueprint** を選び、リポジトリとブランチを指定します。
3. `GEMINI_API_KEY` の入力を求められるので、キーを入力します。
4. デプロイが終わると `https://<サービス名>.onrender.com` で遊べます。

### 手動で作る場合

**New → Web Service** でリポジトリを選び、次のように設定します。

| 項目 | 値 |
|---|---|
| Runtime | Node（`NODE_VERSION=22` を環境変数に追加） |
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Instance Type | Free |
| Health Check Path | `/healthz` |
| Environment | `GEMINI_API_KEY`（必須）と、必要なら下の表の変数 |

`PORT` は Render が自動で設定し、Render 上ではサーバーは自動的に `0.0.0.0` で待ち受けます。
無料インスタンスはしばらくアクセスがないと休止し、次のアクセスで起動します（最初の表示に時間がかかります）。

## 使いすぎ・不正利用の防止

| 対策 | 内容 |
|---|---|
| 課金されないキー | 請求先のないプロジェクトのキーを使えば、無料枠を超えてもエラーになるだけ（最も重要） |
| サイト全体の上限 | 1 日（太平洋時間）あたり `DAILY_CALL_LIMIT` 回、1 分あたり `RPM_LIMIT` 回 |
| 接続元ごとの上限 | IP ごとに 1 日 `IP_DAILY_LIMIT` 回、1 分 `IP_RPM_LIMIT` 回、リクエスト間隔は `IP_MIN_INTERVAL_MS` 以上 |
| 同時実行数 | `MAX_CONCURRENT` 件まで |
| 発言ごとに通信しない | 会話記録をまとめて生成し、再生中は通信しない。同じタブからの生成は 1 件だけ。観察者が割り込んだら古い生成を中止する |
| リトライしない | SDK の自動リトライは無効。Gemini の 429 も再試行しない。通信エラーのやり直しは 3 回まで |
| 出力の上限 | 1 回の生成は最大 36 発言、出力トークンは `GEMINI_MAX_OUTPUT_TOKENS` まで |
| 見ていないときは止まる | 画面を離れた瞬間に再生と生成を止める（戻ると続きから再開）。操作がないまま 8 つの会話を再生したら「まだ見ていますか？」と一時停止 |
| 他サイトからの利用を拒否 | 専用ヘッダーと Origin を確認。リクエストサイズも制限。CSP などのセキュリティヘッダー |
| 緊急停止 | `AI_ENABLED=false` で AI を呼ばず、デモモードだけで動く |
| 上限に達したら | 1 日の上限に達したら、AI ではないと明示したデモモードに切り替えて表示を続ける |

上限の回数はサーバーのメモリ上で数えているので、無料インスタンスが休止・再起動すると数え直しになります。**最終的な歯止めは「請求先のないキーを使うこと」** です。

### 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `GEMINI_API_KEY` | （必須） | Gemini API キー |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | 使用するモデル |
| `GEMINI_MAX_OUTPUT_TOKENS` | `8192` | 1 回の生成（会話記録 1 つ）の最大出力トークン数（思考トークンを含む） |
| `GEMINI_THINKING_LEVEL` | （空） | 思考の深さ（`MINIMAL` / `LOW` / `MEDIUM` / `HIGH`）。空ならモデルの既定値 |
| `AI_ENABLED` | `true` | `false` で AI を止め、デモモードのみにする |
| `DAILY_CALL_LIMIT` | `300` | サイト全体の 1 日あたり呼び出し上限 |
| `RPM_LIMIT` | `10` | サイト全体の 1 分あたり呼び出し上限 |
| `IP_DAILY_LIMIT` | `120` | 接続元ごとの 1 日あたり上限 |
| `IP_RPM_LIMIT` | `8` | 接続元ごとの 1 分あたり上限 |
| `IP_MIN_INTERVAL_MS` | `2500` | 接続元ごとの最小リクエスト間隔 |
| `MAX_CONCURRENT` | `3` | 同時に処理する AI リクエスト数 |
| `GEMINI_TIMEOUT_MS` | `60000` | Gemini への 1 回の呼び出しの制限時間（会話記録をまとめて書くので長め） |
| `UPSTREAM_COOLDOWN_BASE_MS` | `4000` | Gemini が 503 などを返したあと、サーバー全体で呼び出しを控える時間の初期値 |
| `UPSTREAM_COOLDOWN_MAX_MS` | `60000` | 上の待ち時間の上限（失敗が続くと倍々に伸び、成功すると元に戻る） |
| `PORT` / `HOST` | `3000` / `127.0.0.1`（Render では `0.0.0.0`） | 待ち受けポートとアドレス |

## Gemini が不安定なとき（503 など）

Gemini API は混雑時に **HTTP 503（`UNAVAILABLE`, "The model is overloaded"）** を返すことがあります。これは Google 側の一時的な過負荷で、こちらの使いすぎ（その場合は 429）とは別のものです。このアプリは次のように扱います。

- **サーバー**：Gemini の HTTP ステータス・エラーコード・メッセージ・所要時間をログに 1 行で残します（プロンプトや API キーは出しません）。
  ```
  [gemini] error model=gemini-3.5-flash-lite ms=412 http=503 code=UNAVAILABLE message="The model is overloaded. Please try again later." mapped=upstream_unavailable
  [gemini] cooldown 4900ms after upstream_unavailable (consecutive failures: 1)
  ```
  503 / 500 / 502 / 504・分間上限の 429・タイムアウトのあとは、**サーバー全体で少しの間 Gemini を呼ばず**、ブラウザには理由と待ち時間（`Retry-After`）をすぐ返します。待ち時間は失敗が続くほど伸び（上限 60 秒）、成功すると元に戻ります。混雑中に全員が呼び続けて悪化させず、無料枠も使いません。
- **ブラウザ**：「Google の AI（Gemini）が一時的に応答できません（HTTP 503 UNAVAILABLE）。○秒ほど待ってから続けます…」と表示し、ヘッダーは「応答待ち」（意図的な沈黙の「静かな間」とは別）になります。待ち時間はサーバーの指示以上、かつ 6 → 15 → 30 → 45 秒と伸ばします。**5 回続けて失敗したら会話を止め**、理由を表示します（▶ で再開できます）。無限にはやり直しません。
- **どこが返したエラーか**：ログの `[gemini]` 行は Gemini の応答です。ブラウザの表示が「ゲームのサーバーが応答していません（HTTP 503）。起動中かもしれません」のときは、アプリより手前の Render（休止からの起動中・再デプロイ中など）が返したものです。

## デモモード

API キーがないとき、AI が止められているとき、1 日の上限に達したときは、**デモモード** で動きます。
デモモードの会話は AI ではなく、用意した台本を順番に再生しているだけです。ヘッダーに `DEMO` バッジ、開始時と切り替え時に「AI ではありません」という表示が出ます。デモモードでは API は一切呼び出されません。

## 遊び方

- 「会話をはじめる」を押すと、二人が話し始めます。あとは眺めているだけで会話は続きます。
- 画面下の入力欄から話しかけられます（100 字まで）。話しかけると、二人は話を止めてあなたの発言に反応します。
- 右下のボタンで一時停止 / 再開。一時停止中に話しかけると、会話が再開してあなたの発言に反応します。
- ほかのアプリやタブに移ると止まり、戻ると続きから再開します。同じタブで再読み込みした場合は「続きを見る」か「新しい会話をはじめる」を選べます。

## しくみ

### 二人

`server/conversation.mjs` の `CHARACTERS` に定義しています。

- **レオ**：直感・想像・連想が得意。好奇心旺盛で、気になったことをすぐ口にする。とっぴな仮説も遠慮なく出し、たとえ話で説明するのも得意。感情や興味が表に出やすい。
- **ミナ**：論理・分析・因果関係の整理が得意。好奇心旺盛で、疑問を放っておけない。根拠や前提を確かめながら考え、必要なら自分から直感的な仮説も出す。ふだんは落ち着いているが、興味を持つと前のめりになる。

二人の知性に上下はなく、「いつもレオがとっぴ・いつもミナが正しい」という形にはしません。二人とも自分なりの意見を持ち、考えを変えることも変えないこともあり、間違いを認め、分からないことは分からないと言います。二人の関係は定義しません。難しい言葉は使わず、自然な話し言葉で話します。

### 会話記録をまとめて生成し、ゲーム側で再生する

Gemini に **一連の会話記録（エピソード）をまとめて 1 回で生成** させ、ブラウザがそれを一発言ずつ再生します。発言ごとの通信はしません。

```
ブラウザ                                     サーバー                         Gemini
 再生が終わった / 観察者が話しかけた ─ /api/episode ─▶ 上限・混雑の確認 ─ 1 回 ─▶ 会話記録（JSON）
 一発言ずつ再生（間・表情・口・動作）  ◀─ 検証済みの会話記録 ──
 再生中は通信しない
```

通信するのは、(1) 記録を最後まで再生し終えて次の記録が必要になったとき、(2) 観察者が話しかけたとき、だけです。同じタブからの生成は常に 1 件だけです。

会話記録は JSON で、次の内容を含みます。

- 会話全体: 概要、話題、問題の有無・種類・状態（解決 / 未解決 / 次回に続く）、結論または未解決の理由、次の会話につながること（後回しにした疑問など）
- 問題: 問い、レオの仮説、ミナの仮説、検討したこと、結論、残った論点
- 発言ごと: 話者、内容、表情、動作、発言の種類（雑談・冗談・問い・仮説・反論・譲歩・ひらめき・結論など）、会話の状態、発言前の間

サーバーは返ってきた JSON を検証し、欠けた項目は既定値で補い、不正な発言・連続した重複・前回の繰り返しは取り除きます。出力が上限で途中で切れたときは、完全な発言だけを取り出して使います（追加の呼び出しはしません）。再生できる発言が 2 つ未満なら、形式エラーとして扱います。

### 会話の流れ

会話は内部的に次の状態で進みます（画面には出しません）。各発言に Gemini が状態を付けます。

1. **FREE**：自由な日常会話
2. **DISCOVERY**：「それって不思議じゃない？」と問題を見つける
3. **EXPLORATION**：それぞれの仮説を出し、比べ、反論し、考えを直す
4. **RESOLUTION**：結論をまとめる（正解がある問題は正確さを重視。分からなければ未解決にする）
5. **AFTERMATH**：感想、冗談、雑談に戻る、関連する疑問に広がる

毎回問題から始めるわけではなく、雑談だけで終わる回もあります。会話の長さは問題の複雑さや面白さに応じて Gemini が決めます（最大 36 発言）。

- 問題を出したら、原則として解決まで取り組みます。途中で浮かんだ別の疑問は「後回し」にして、あとで取り上げます。
- 結論が出なかった問題や、次回も続けたい問題は、次の会話で続きから話します。
- 始まり方が同じにならないよう、日常の話題の種を毎回ランダムに渡し、最近話した話題は避けるよう伝えます。

### 再生

- 発言の前の間（なし / 短い / 長い）を再現します。長い間は考え込む沈黙として、吹き出しを出さずに「静かな間」と表示します。
- 話す人は記録どおりの表情と動作（うなずく、首をかしげる、身を乗り出す、笑う、肩をすくめる、目をそらす、お茶を飲む、考える）をし、話している間は口が動きます。
- 聞いている人は、相手の発言の種類に合わせて控えめに反応します（仮説には考える顔、反論には困った顔、冗談には笑顔など）。
- 一つの会話が終わると少し余韻をおき、次の記録を生成している間は二人が考える表情になり、「考え中」と表示します（API の応答待ち。意図的な沈黙とは区別しています）。

### 観察者の参加（割り込み）

観察者が話しかけると、

1. 再生中の発言をその場で止め（吹き出しは「…」で途切れる）、まだ再生していない記録は捨てます。
2. それまでに再生された発言、途中まで話していた発言、その時点での問題と二人の仮説を残します（まだ話していない結論は含めません）。
3. 生成中の古いリクエストがあれば中止し、その結果は使いません。
4. 観察者の発言を最優先で送り、それを踏まえた新しい会話記録を生成して再生します。

二人は観察者の発言に自然に反応し、必要なら仮説や結論を変えます。答えを教えられたら、それを受け止めたうえで話を進めます。二人が同じ回数ずつ答える必要はありません。

### 会話の文脈（短期的なものだけ）

次の記録を作るために、**このタブの sessionStorage にだけ** 次のものを置きます。サーバーやデータベースには保存しません。

- 直近 3 つの会話の概要と、その問題の結末
- 続いている問題（問い・二人の仮説・検討したこと）
- 後回しにした疑問（最大 5）、最近の話題（最大 10）
- それぞれのメモ（相手の癖、考えが変わったことなど。最大 6）
- 直近 12 発言と、再生中の記録の残り（再読み込みしても続きから再生できる）

タブを閉じるか「新しい会話をはじめる」を選ぶと消えます。

### 通信量

- 1 回の生成で 6〜36 発言の会話になるので、発言ごとに通信していた以前よりリクエスト数は大きく減ります。
- 再生中は通信しません。生成は同じタブから同時に 1 件だけです。
- 操作がないまま 8 つの会話を再生したら「まだ見ていますか？」と一時停止します。画面を離れると、再生も生成も止まります。
- 503 などの一時的な障害には、前述の待ち時間・クールダウンで対応します。無限にはやり直しません。

## スマートフォン対応

- 画面全体を表示領域ぴったりの固定レイアウト（`position: fixed` + `100dvh`）にし、ページ自体は縦にも横にもスクロールしません。
- 仮想キーボードが出たときは `visualViewport` の実寸に合わせて全体を縮め、入力欄が常に見えるようにしています。
- ノッチやホームインジケーターは `env(safe-area-inset-*)` で避けます。
- キャラクターの大きさは、ステージの **幅と高さの両方** から決めます（コンテナクエリの `cqw` / `cqh`）。どの画面でも二人と吹き出しの領域が両方収まります。
- 吹き出しは古いものから消し、それでも入らないときだけ文字を詰めます。

## 開発

```bash
npm test
```

ユニットテスト（人格・プロンプト・会話記録の検証・途中で切れた出力の取り出し・上限）と、モックの Gemini サーバーに対して実際にサーバーを起動する結合テストが走ります。API キーは不要で、本物の Gemini には接続しません。

```bash
npm run dev
```

ファイル変更時にサーバーを自動再起動します。

```
server/
  index.mjs         HTTP サーバー（静的配信・API・呼び出し元の確認）
  ai.mjs            Gemini API 呼び出し・エラー変換
  limits.mjs        使いすぎ防止の上限管理
  conversation.mjs  人格・会話記録のプロンプト・出力の検証
  demo.mjs          デモモードの台本（AI ではない）
public/
  index.html / style.css / app.js   画面と会話記録の再生
test/               テスト
render.yaml         Render 用の Blueprint
```
